# Architecture

## 新增核心流程

1. 登录后服务员进入 `/tables` 图形化选桌页。
2. 选择绿色桌开台并填写人数，或选择两张绿色桌拼桌开台。
3. 进入 `/order` 点餐页按分类下单。
4. 在点餐页查看已点餐品与总价。
5. 点击结账确认，系统自动关台并返回选桌。

## 稳定性基线（弱网场景）

1. 下单请求支持幂等键，服务员重复提交不会重复出单。
2. 开台/拼桌/结账/关台使用数据库事务 + advisory lock，避免并发冲突。
3. 打印采用 `print_jobs` 队列，提交订单后异步消费，失败自动记录并可重试。
4. 管理端收入统计仅计算 `paid` 订单，口径与结账一致。
5. 前端统一请求超时与有限重试，降低弱网卡顿和误触发重试风险。

## 权限模型

- 服务员（waiter）
  - 可点餐、开台/拼桌、查看“今天订单”及订单明细
- 经理（manager）
  - 拥有服务员全部能力
  - 可删除任意订单
  - 可使用收入页与菜单管理（列表式全量管理）

## 数据模型

- `table_sessions`
  - 开台记录（桌号、人数、开台时间、关台时间）
- `table_session_tables`
  - 开台桌号映射（支持拼桌：一个 session 对应两张基础桌）

## 颜色状态

- 绿色：未开台（可开台）
- 红色：已开台（可继续点餐或结账）

## 关键页面

- `/tables`：选桌与拼桌
- `/order`：点餐 + 已点餐品 + 结账
