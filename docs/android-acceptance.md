# Android 对照验收

基线：网页 `ee66a93`，原生内部版 `0.1.0-internal`。此清单供后续联调执行；“已实现”不等于“门店已验收”。真实输入、金额、截图和纸单由受控环境/现场补齐。

| 范围 | 已有本地验证 | 仍需真实连接/现场核对 |
| --- | --- | --- |
| 登录/导航 | 经理进订单、服务员进桌台；角色入口；账号草稿隔离 | 实际账号、过期 token、权限配置 |
| 桌台 | 开台→点菜→结账关台；物理三列截图 | 所有桌号/金额、拼桌/取消拼桌、并发开台 |
| 点菜/购物车 | 普通添加立即开购物车；离开重入保留；成功清空 | 全菜单、套餐、下架项、自定义菜、长菜单性能 |
| 海鲜/备注 | 100g/只计量规则；做法、备注、中英切换操作 | 全部实际海鲜名、单价、厨房单备注与合计 |
| 提交恢复 | 丢失回执复用原键；repository 重建恢复；只读确认只产生一次 POST；旧接口 404 回退；存储失败阻止发单 | 真断网/杀进程、多端并发、订单已保存但纸单未知 |
| 账单/打印/结账 | 流程、80 金额样例、打印请求路径、结账桌台空闲 | 数据库、费用、退菜、取消、反结账、实体打印 |
| 订单管理 | 页面、经理入口；既有服务端会计回归 | 明细、退菜、取消、折扣/服务费、删除、反结账 |
| 收入/导出 | 收入界面、月份范围/时区规则；HTTP CSV 处理 | 系统保存/取消/失败、CSV 列与金额、跨月跨年 |
| 费用/热销/设备/权限/菜单 | 五页加载原生控件；共享配置生成检查 | 每个编辑/保存/删除、失败重试、队列/设备及测试打印 |
| 存储/生命周期 | 真 Keystore 加密、随机 IV、防存储键互换；持久化对象重建 | 杀进程、锁屏、低存储、覆盖升级、目标机型 |

本地 HTTP 与 Compose 模拟测试彼此独立，尚未连接实际 Next.js + PostgreSQL 完成原生端到端流程。

## 执行顺序

1. 记录网址、部署 commit、设备/Android 版本；网页与 APK 使用同一受控数据集，不将验收单混进营业数据。
2. 两个角色分别执行：开台→普通菜→海鲜备注→跨类→提交→追加→账单→退菜→费用→打印→结账，每步记录画面、接口、金额和纸单。
3. 验证拼桌/取消拼桌、关台、取消/删除/反结账、临时/永久加菜、分类及批量编辑、费用、权限、设备工具。
4. 两端操作同桌，覆盖提交与结账竞争；断网、重复点击、丢失回执、后台回收后重开。确认订单和打印任务数量。
5. 单月/跨月/跨年 CSV 按相同时区逐列比较，核对收入、费用和热销。
6. 分别核验订单已保存、任务已入队、provider 接收、实际出纸；核对厨房单/收据的菜名/做法、桌号、人数和份数。
7. 小屏/平板/横屏、大字体、软键盘、返回、锁屏、升级，检查输入可达、草稿可恢复。
8. 小范围试用并保留网页；出现阻止营业或金额/打印差异时回到网页，同一未确认订单不要盲目重下。阻断项关闭后换正式签名包。

## 需要裁定

- 真实网址/部署版本、可测试环境、只读恢复接口是否部署。
- 设备型号/Android 版本。工程起点 API 26 不代表所有版本均实机通过。
- 建议先店内安装 APK；正式包签名的保管人与备份位置待确认。
- cashier/ops 当前网页跳转收入，summary 没有日常导航入口；如现场使用历史深链接或外部入口，补入验收。

每项记录：环境、角色、输入、网页结果、安卓结果、纸单、证据、通过/失败、负责人、日期。无证据保持“待验收”。
