# 点餐系统稳定性优化说明

这次优化的目标很简单：让酒店员工每天打开系统就能用，网络慢、手机性能一般、打印机不稳定时，也尽量不要影响正常点餐。

## 我们解决了什么问题

### 1. 打开系统更稳定

之前系统在手机上有机会出现突然刷新、闪屏、打不开的情况。

现在我们做了这些处理：

- 系统更新时不再强制刷新当前页面。
- 手机浏览器存储异常时，不会直接导致页面白屏。
- 页面出错时，会显示“重试”或“回到登录”，不会只剩空白页面。

### 2. 网络慢时更好用

酒店网络只有 50Mbps，而且多人共用时会有延迟。

现在我们做了这些处理：

- 菜单会保存在手机本地。
- 网络慢时，先显示上一次成功加载的菜单。
- 后台再慢慢刷新最新菜单。
- 请求有超时和重试，不会一直卡住转圈。

### 3. 打印机不会拖垮点餐

之前系统接入打印机后更容易出问题。核心原因是：打印机或云打印服务慢的时候，可能影响点餐流程。

现在我们做了隔离：

- 员工提交订单时，系统先保存订单。
- 保存成功后，打印任务进入队列。
- 打印机会在后台处理。
- 打印机慢、离线、网络不稳时，不应该再影响订单保存。

这意味着：就算打印机当天不稳定，员工也可以继续点单，之后再处理打印。

### 4. 防止重复下单

弱网时，员工可能会多点几次“提交订单”。

现在系统会尽量识别重复提交，减少重复订单的风险。

### 5. 删除无关项目

之前仓库里有一个误创建的 `quant-demo` 目录，和酒店点餐系统没有关系。

这次已经把它彻底删除，并且去掉了文档和配置里的相关引用。以后维护时不会再被它干扰。

## 现场遇到问题时怎么办

### 如果打印机不稳定

可以把自动唤醒打印关闭：

```env
PRINT_WAKE_ON_ORDER=false
```

关闭后：

- 订单照常保存。
- 打印任务照常排队。
- 系统不会在员工下单时主动连接打印机。
- 管理员可以在设备/打印页面处理打印任务。

这是一种“保命模式”：先保证点餐和收银不中断。

### 如果网络很慢

员工可以继续使用已经缓存过的菜单。

如果菜单没有刷新成功，系统会提示网络问题，但不会轻易白屏。

## 这次验证过什么

我们已经检查并通过：

- 登录页可以打开。
- 桌台页可以打开。
- 点餐页可以打开。
- 菜单接口正常。
- 打印健康检查权限正常。
- 系统生产构建成功。
- 自动测试全部通过。

## 简单总结

这次不是增加复杂功能，而是让系统更抗风险：

- 手机异常时不容易白屏。
- 网络慢时不容易卡死。
- 打印机异常时不影响点餐。
- 菜单能缓存，打开更快。
- 无关项目已删除，后续维护更清晰。

最终目标是：酒店员工每天打开就能用，出了小问题也能继续营业。
