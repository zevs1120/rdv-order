# 芯烨云后台接入重整（2026-09-20）

## 范围与事实

用户要求继续使用现有芯烨云网络打印机，按官方规范重新整理接入，不绕过云端、不新增硬件、不改变 APP 操作。本轮只修改后台源代码；现有 APK 仍为 1.1.3/code12。

现场已经确认：官方接口纯文字测试 RDV-CLOUD-884598 也完全没有出纸。该次请求 HTTP200/code0，云订单 OM26092014095885012205，后续 queryOrderState=true。这证明当前云端报告不能作为实物验收；不能从这组证据断言物理离线，也不能声称重写后台必然修复云端到机器的问题。停止反复要求用户现场检查，不再追加测试纸。

## 最终实现

- `lib/xpyun-client.ts` 统一配置解析、HTTPS JSON 请求、秒级时间戳、SHA1 签名、提交和设备状态查询。厨房单、账单、自检统一调用；业务查询、金额、权限、APP 和队列领取不改。
- 请求禁止跳转与缓存，避免把签名/内容转发到重定向地址；当前账户、设备及官方节点保持不变。保留已有环境变量别名。
- 严格验证官方整数返回码和非空云订单号。null、字符串零、缺失订单号不能当成功；1013 去重回执没有可查询订单号，保留未知结果并停止重发，不伪造成功。
- 官方 1004 添加订单失败最多重试一次；1006 日期错误、鉴权和绑定等错误不重试。传输未知最多一次同内容/同去重编号重试，刷新签名；第二次失败不得覆盖第一次未知结果。未知结果不走备用通道、不留给 worker 盲目重发。
- 保留原来未指定 mode 的在线检查语义；不擅自开启离线延迟出纸。voice 只允许打印 API 的 0–3，mode 只允许 0–1，显式错误配置在发送前失败。单份策略和账单固定一份保留。
- 票据正文、菜品、数量、金额及填写字段保留；居中行按官方规则把 BR 放入对齐标签，标题使用单层 CB，空白行不生成空字体标签。
- 删除超长票据自动删行的实现，完整提交内容。超过厂家 GBK 12K 限制时由厂家返回1007并明确失败；本轮不自动拆单，避免部分成功后的重复打印。未声称已支持超长票据多单交付。
